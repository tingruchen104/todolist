# Prototype 流程紀錄（欄位定義 + 回顧判準）

目的:收集資料,回答一個還不確定的問題——**「.vue 產完就夠用」與「需要轉 Figma 調整」的比例各多少、以及 PM 到底在調整什麼。** 在累積足夠資料前,先**不要**投入建 Figma 元件庫 / Code Connect,等有 5〜10 筆再回頭決定。

> **紀錄落在哪**:目的地的 `prototypes/prototype-log.md`(Markdown 表格,一頁一列)。`/prototype` 產完每頁先建/補一列(「是否轉 Figma」預設「否」、原因留空);之後若走 `/prototype-figma`,由該指令回填「是」與原因。由 **Claude 代 PM** 維護,使用者不碰檔案。這份文件只放「欄位意義」與「回顧判準」,不是紀錄本體。

## 欄位意義

- **① 是否轉 Figma** — `否`(`.vue` 已足以交付、直接交) / `是`(走 `/prototype-figma` 轉出調整)
- **② 需調整 Figma 原因** — 轉 Figma 時填,擇一或並列;未轉就留白(`—`):
  - `顏色間距` — 只是微調樣式
  - `版面結構` — 要換排版、探索多種設計
  - `互動` — 要真元件的真實行為(真表單驗證、真操作)
  - `給人看` — **有其他人(主管、業務、客戶等非工程的人)需要「自己」開來看 prototype**,而他們沒有啟 localhost 的能力。註:若都是 PM 自己 demo(當面或遠端螢幕分享),不算這一項——開 `.vue` localhost 即可

表格格式(Claude 代記,`/prototype` 建列、`/prototype-figma` 回填):

```markdown
| 日期 | page-name | 畫面名稱 | 是否轉 Figma | 需調整 Figma 原因 |
| --- | --- | --- | --- | --- |
| <日期> | <page-name> | <畫面名稱> | 否 / 是 | <…/-> |
```

## 回顧檢查點(累積 5〜10 筆後)

看兩件事再決定投資:

1. **比例** —「夠用直接交 .vue」vs「要轉 Figma」各佔多少。
2. **調整性質**(第 ② 欄的分布):
   - 多是 `顏色間距` → 該**改進 `/prototype` 的產出**,不是投 Figma。因為這是生成時就做錯的瑕疵(顏色間距本來就由 `design-system.md` 定義):在 Figma 事後調只修好這頁、每頁重犯;改 `/prototype`(prompt / token)一次修,之後每頁都對。
   - 多是 `版面結構` → Figma 才有價值,值得投**元件庫 + Code Connect**。
   - 多是 `給人看` → 先分兩種(前提:不部署 `.vue`,工程不為 prototype 花部署成本):
     - **只是要看畫面** → PM 從 localhost **截圖 / 錄操作影片**分享即可,準確、免費、零失真,**不需 Figma**。
     - **其他人要自己互動點過、或要留言標註協作** → 此時 **Figma 是唯一選項**,接受失真為代價。這也是 Figma 在本流程唯一站得住的理由;**唯有這是 PM 轉 Figma 的主因時,那份 Figma 的保真度才重要,元件庫投資才有意義。**
